# 游戏动态参数配置开发文档

本文档旨在为开发人员提供关于如何新增、修改和使用游戏内动态参数的详细指南。

## 1. 核心设计

游戏的核心参数采用数据库驱动的动态配置方案，存储在 `game_config` 表中，并通过 `GameConfig.java` 类加载到内存中供游戏逻辑调用。这种设计使得我们可以在不重启服务器的情况下，通过修改数据库或调用GM指令来实时调整游戏行为。

### 1.1 数据表结构 (`game_config`)

`game_config` 表是所有动态参数的中心存储库。

| 字段名 | 类型 | 描述 | 示例 |
| :--- | :--- | :--- | :--- |
| `id` | `bigint` | 主键ID | `1001` |
| `config_type` | `varchar` | **配置大类**。用于区分参数的作用域。 | `server`, `world` |
| `config_sub_type` | `varchar` | **配置子类**。用于对大类进行分组。 | `Game Mechanics`, `0` (worldId) |
| `config_clazz` | `varchar` | **参数值类型标记**。普通参数写 Java 类型；JSON 参数统一写 `json`，不写 `json:object`、`json:array` 等变体。 | `java.lang.Boolean`, `java.lang.Integer`, `json` |
| `config_code` | `varchar` | **参数的唯一编码** (Key)。 | `item_recovery_enabled` |
| `config_value` | `varchar` | **参数的值** (字符串形式)。 | `true`, `1000000` |
| `config_desc` | `varchar` | **参数的简短描述**。 | `item_recovery_enabled` |

### 1.2 核心加载类 (`GameConfig.java`)

`GameConfig.java` 是一个单例类，在服务器启动时，它会从 `game_config` 表加载所有配置项到内存中的一个 `JSONObject` 对象里。它提供了丰富的静态方法，用于在游戏代码中方便地获取这些配置值。

- **内存结构**: 所有配置项被组织成一个三级嵌套的JSON结构：`大类 -> 子类 -> 编码 -> {value, clazz}`。
- **热重载**: `GameConfig.java` 中的 `update` 方法支持热重载。当通过后台管理界面修改参数时，该方法会被调用，不仅会更新内存中的值，还会执行特定的硬编码逻辑来立即应用某些需要特殊处理的参数（如世界倍率、雇佣商店持续时间等）。

### 1.3 JSON 参数分层边界

JSON 参数是动态参数系统的复杂值扩展，用于存放对象、数组、二维数组、规则表等结构化配置。当前统一约定如下：

| 层级/场景 | JSON 处理策略 | 说明 |
| :--- | :--- | :--- |
| `GameConfig.java` 静态缓存层 | 保留 fastjson2/`JSONObject` 作为内部缓存实现 | `GameConfig` 初始化早于完整 Spring Bean 生命周期，不直接注入或创建 Jackson `ObjectMapper`。 |
| `config_clazz` 标记 | 只允许写 `json` | `json` 只表示“该值是 JSON 结构”，不表达 Map、数组、DTO 或泛型类型。 |
| `GameConfig` 读取 JSON | 默认返回原始 JSON 字符串 | `getServerJsonString()` / `getWorldJsonString()` 不做强类型解析。 |
| Spring Bean：Controller / Service / DTO | 统一使用注入的 Jackson `ObjectMapper` | 新增、更新、保存校验、强类型解析都放在 Spring Bean 层，继承项目统一 Jackson 配置。 |
| 前端参数管理 | 对 `configClazz === 'json'` 使用 JSON 编辑器 | 负责生成合法 JSON 字符串，业务语义仍由后端服务控制。 |

因此，**不要因为 `GameConfig` 内部使用 fastjson2，就要求其它业务类也跟随改用 fastjson2**。统一规范是：`GameConfig` 只作为启动早期静态缓存层保留历史实现；业务 JSON 解析、接口 JSON、保存校验和强类型转换仍统一使用 Jackson。

## 2. 如何新增或修改游戏参数

### 2.1 步骤一：编写 Flyway SQL 迁移脚本

所有对 `game_config` 表的结构性或数据性变更，都**必须**通过 [Flyway](https://flywaydb.org/) 数据库迁移脚本来完成。

1.  **创建脚本**: 在 `src/main/resources/db/migration/` 目录下创建一个新的 `.sql` 文件。
2.  **命名规范**: 文件名必须遵循 Flyway 的版本号命名规范，例如 `V2.0.0.3__add_new_feature_configs.sql`。
3.  **编写 `INSERT` 语句**:
    -   参照 `V2.0.0.2__insert_item_recovery_config.sql` 的格式。
    -   为每一个新参数编写一条 `INSERT INTO game_config (...) VALUES (...)` 语句。
    -   **务必**仔细填写 `config_type`, `config_sub_type`, `config_clazz`, `config_code`, `config_value` 和 `config_desc` 字段。

    **示例：新增一个名为 `new_feature_enabled` 的布尔型参数**
    ```sql
    -- /src/main/resources/db/migration/V2.0.0.3__add_new_feature_configs.sql

    INSERT INTO `game_config`(`config_type`, `config_sub_type`, `config_clazz`, `config_code`, `config_value`, `config_desc`)
    VALUES
        ('server', 'New Feature', 'java.lang.Boolean', 'new_feature_enabled', 'true', 'Controls the activation of the new feature.');
    ```

### 2.2 步骤二：添加多语言描述 (推荐)

为了让后台管理界面能显示参数的友好名称和详细描述，需要向 `lang_resources` 表中插入对应的多语言资源。

1.  **在同一个 SQL 脚本中操作**: 继续在刚才创建的 Flyway 脚本中添加 `INSERT` 语句。
2.  **编写 `INSERT` 语句**:
    -   `lang_type`: 语言代码，如 `zh-CN`, `en-US`。
    -   `lang_base`: 固定为 `game_config`。
    -   `lang_code`: **必须**与 `game_config` 表中的 `config_code` 完全一致。
    -   `lang_value`: 该参数在该语言下的详细描述。

    **示例：为 `new_feature_enabled` 添加中英文描述**
    ```sql
    -- /src/main/resources/db/migration/V2.0.0.3__add_new_feature_configs.sql

    -- ... (上一段INSERT语句) ...

    -- 中文描述
    INSERT INTO `lang_resources`(`lang_type`, `lang_base`, `lang_code`, `lang_value`)
    VALUES
        ('zh-CN', 'game_config', 'new_feature_enabled', '是否开启“新功能”。true=开启，false=关闭。');

    -- 英文描述
    INSERT INTO `lang_resources`(`lang_type`, `lang_base`, `lang_code`, `lang_value`)
    VALUES
        ('en-US', 'game_config', 'new_feature_enabled', 'Whether to enable the "New Feature". true=enabled, false=disabled.');
    ```

### 2.3 修改现有参数

修改现有参数的默认值，同样建议通过 Flyway 脚本完成，以保证所有开发和部署环境的一致性。使用 `UPDATE` 语句即可。

```sql
-- /src/main/resources/db/migration/V2.0.0.4__update_recovery_fee.sql

UPDATE `game_config`
SET `config_value` = '2000000'
WHERE `config_code` = 'item_recovery_base_fee_meso';
```

### 2.4 新增 JSON 参数

当参数值是对象、数组、二维数组或规则表时，应使用 JSON 参数：

1. `game_config.config_clazz` 固定写 `json`。
2. `game_config.config_value` 必须是标准 JSON 字符串：
   - 对象示例：`{"enabled":true,"threshold":0.9}`
   - 数组示例：`["a","b"]`
   - 二维数组示例：`[[0,129,0.3],[130,255,0.9]]`
3. 不允许使用 JSONC 注释、尾逗号、未加引号的 key、`json:object`、`json:array`、`json:DTO` 等扩展格式。
4. 若旧配置实际是 JSON 但 `config_clazz` 仍是 `java.lang.String` / `java.util.Map` / DTO 全限定名，迁移时应先确认后端已兼容 `json`，再用 Flyway 把 `config_clazz` 改为 `json`。

**示例：新增一个 JSON 规则参数**

```sql
-- /src/main/resources/db/migration/V2.0.0.5__add_json_rule_config.sql

INSERT INTO `game_config`(`config_type`, `config_sub_type`, `config_clazz`, `config_code`, `config_value`, `config_desc`)
VALUES
    ('server', 'Game Mechanics', 'json', 'new_rule_config', '{"enabled":true,"rules":[{"minLevel":1,"maxLevel":30,"rate":0.5}]}', 'new_rule_config');

INSERT INTO `lang_resources`(`lang_type`, `lang_base`, `lang_code`, `lang_value`)
VALUES
    ('zh-CN', 'game_config', 'new_rule_config', '新规则配置，包含开关和等级区间规则。');
```

如果该 JSON 参数需要字段级说明，推荐额外写入 `lang_base = game_config_json_i18n` 的说明 JSON：

```sql
INSERT INTO `lang_resources`(`lang_type`, `lang_base`, `lang_code`, `lang_value`)
VALUES
    ('zh-CN', 'game_config_json_i18n', 'new_rule_config',
     '{"_self":"新规则配置","enabled":"是否启用","rules":"规则列表","rulesItem":{"minLevel":"最低等级","maxLevel":"最高等级","rate":"倍率，取值 0~1"}}');
```

数组或二维数组字段说明可使用 `_item` / `_columns` 约定：

```json
{
  "_self": "装备等级范围与概率配置",
  "_item": "每一行表示一个等级范围规则",
  "_columns": {
    "0": "最低装备等级",
    "1": "最高装备等级",
    "2": "触发概率，取值 0~1"
  }
}
```

## 3. 如何在游戏代码中调用参数

`GameConfig.java` 提供了多种便捷的静态方法来获取配置值。核心原则是：**根据参数的 `config_type` 和 `config_code` 来选择合适的获取方法**。

### 3.1 获取 `server` 类型的参数

`server` 类型的参数是全局唯一的，与具体的世界（World）无关。

-   **方法**: 使用 `getServer...()` 系列方法。
-   **示例**: 获取 `item_recovery_enabled` (布尔值) 和 `item_recovery_base_fee_meso` (长整型)。

```java
// 在任意业务逻辑代码中

// 获取布尔值，如果未配置，默认为 false
boolean isRecoveryEnabled = GameConfig.getServerBoolean("item_recovery_enabled");

if (isRecoveryEnabled) {
    // 获取长整型，如果未配置，默认为 100000L
    long baseFee = GameConfig.getServerLong("item_recovery_base_fee_meso", 100000L);
    
    System.out.println("物品找回功能已开启，基础费用为: " + baseFee);
}
```

**常用 `getServer...` 方法列表:**
- `getServerBoolean(key, [defaultValue])`
- `getServerInt(key, [defaultValue])`
- `getServerLong(key, [defaultValue])`
- `getServerDouble(key, [defaultValue])`
- `getServerString(key)`
- `getServerJsonString(key)`: 获取 `json` 参数原始字符串，不做强类型解析。
- `getServerObject(key, Class<T> clz)`: 用于获取复杂的JSON对象。

### 3.2 获取 `world` 类型的参数

`world` 类型的参数是与特定世界（频道）绑定的，例如每个频道的经验倍率可以不同。

-   **方法**: 使用 `getWorld...()` 系列方法，并且**必须传入 `worldId`**。
-   **示例**: 获取某个世界（如 `worldId = 0`）的经验倍率。

```java
// 通常在与玩家或世界相关的代码中
// int worldId = player.getClient().getWorld();

int worldId = 0; // 假设在 0 频道
float expRate = GameConfig.getWorldFloat(worldId, "exp_rate");

System.out.println("世界 " + worldId + " 的经验倍率是: " + expRate);
```

**常用 `getWorld...` 方法列表:**
- `getWorldBoolean(worldId, key)`
- `getWorldInt(worldId, key)`
- `getWorldFloat(worldId, key)`
- `getWorldString(worldId, key)`
- `getWorldJsonString(worldId, key)`: 获取指定世界的 JSON 参数原始字符串，不做强类型解析。
- `getWorldObject(worldId, key, Class<T> clz)`

### 3.3 JSON 参数读取与强类型解析

JSON 参数读取遵循“缓存层只取字符串，业务层用 Jackson 解析”的原则。

#### 3.3.1 在静态/底层代码中只取原始字符串

```java
String json = GameConfig.getServerJsonString("new_rule_config");
if (!json.isEmpty()) {
    // 短期兼容场景可自行解析；新增 Spring Bean 业务优先使用 ConfigService.readJson。
}
```

#### 3.3.2 在 Spring Bean 中使用统一 Jackson 解析

`ConfigService` 已提供 JSON 工具方法：

- `writeJson(Object value)`：使用项目统一 `ObjectMapper` 写出标准 JSON 字符串。
- `readJson(String configCode, Class<T> clazz, T defaultValue)`：按 Class 读取 JSON 参数。
- `readJson(String configCode, TypeReference<T> typeReference, T defaultValue)`：按 Jackson 泛型类型读取 JSON 参数。

示例：

```java
@Service
@AllArgsConstructor
public class NewRuleService {
    private final ConfigService configService;

    public NewRuleConfig loadConfig() {
        return configService.readJson(
                "new_rule_config",
                NewRuleConfig.class,
                NewRuleConfig.defaultConfig()
        );
    }
}
```

如果要保存或自动创建 JSON 参数，应先用 `ConfigService.writeJson()` 写成标准 JSON，再通过 `upsertServerConfig(..., "json", jsonValue, ...)` 保存。

#### 3.3.3 保存校验

后台参数新增/更新时，如果 `configClazz = 'json'`，`ConfigService` 会用注入的 Jackson `ObjectMapper.readTree()` 校验 JSON 格式。非法 JSON 会被拒绝并返回中文错误提示。

### 3.4 如何实现参数的热重载

对于某些需要立即生效的参数，光修改数据库和内存中的值是不够的，还需要执行特定的业务逻辑。这部分代码需要硬编码在 `GameConfig.update()` 方法中。

1.  **定位 `update` 方法**: 打开 `GameConfig.java`，找到 `public static void update(GameConfigDO gameConfigDO)` 方法。
2.  **添加 `case` 分支**: 在 `switch (gameConfigDO.getConfigCode())` 语句块中，添加一个新的 `case`。
3.  **编写重载逻辑**: 在 `case` 中编写当该参数被更新时需要执行的代码。

**示例：为 `new_feature_enabled` 添加热重载逻辑**

```java
// in GameConfig.java

public static void update(GameConfigDO gameConfigDO) {
    // ... (前面的代码) ...

    // 重载其余部分
    switch (gameConfigDO.getConfigCode()) {
        case "allow_steal_quest_item" -> MonsterInformationProvider.getInstance().clearDrops();
        // ... (其他 case) ...

        // 新增的热重载逻辑
        case "new_feature_enabled":
            boolean enabled = Boolean.parseBoolean(gameConfigDO.getConfigValue());
            NewFeatureManager.getInstance().setEnabled(enabled);
            Server.getInstance().broadcastMessage(CWvsContext.serverNotice(6, "[系统] 新功能已" + (enabled ? "开启" : "关闭") + "。"));
            break;
    }
}
```

通过这种方式，当管理员在后台管理界面修改 `new_feature_enabled` 参数并保存后，`GameConfig.update()` 方法会被调用，从而立即执行我们新加的逻辑，实现真正的动态调整。

JSON 参数也可以在 `GameConfig.update()` 中添加热重载分支。分支内不要在 `GameConfig` 里直接解析复杂业务 DTO，而应调用 Spring Bean 的重载方法，由 Spring Bean 使用 Jackson 完成解析。例如 `traceability_rules` 更新后触发 `TraceabilityConfigService.reloadConfig()`。

## 4. 后台 JSON 编辑器能力

`gms-ui` 参数管理页面已经支持 `config_clazz = 'json'` 的可视化编辑：

- JSON 类型下拉项：新增或编辑配置时可选择 `JSON`。
- 模态框放大：JSON 配置使用更宽的编辑窗口，普通配置仍保持原有输入体验。
- 多语言说明：普通参数描述只编辑当前前端语言对应的 `game_config` 记录；JSON 字段级说明只编辑当前前端语言对应的 `game_config_json_i18n` 记录，不在前端写死中英文切换。
- 列表描述列：普通参数显示 `game_config` 的当前语言描述；JSON 参数优先显示 `game_config_json_i18n` 当前语言说明 JSON 的 `_self` 文案。
- 源码编辑：支持粘贴、格式化、压缩标准 JSON。
- 视图编辑：支持对象/数组树形展示，key/value 就地编辑，并在每个节点上方显示当前节点说明；说明过长时前端会省略显示，鼠标悬停可查看完整内容。
- 字段说明编辑：进入视图修改模式后，可直接在节点上方修改该节点说明，保存时写回 `game_config_json_i18n.lang_value` 的 JSON 结构。
- 节点操作：支持新增、删除、复制、类型切换、展开/折叠。
- 排序能力：数组/对象子节点可调整顺序，拖拽后会刷新节点路径、层级和下标元数据。
- 搜索能力：支持按 key/value 搜索并高亮匹配项，可跳转上一个/下一个匹配。
- 撤销/重做：树编辑和源码同步操作可回退。
- 保存保护：非法 JSON、根节点非对象/数组等情况会阻断保存。

前端保存时仍然只提交字符串形式的 `configValue`，不会改变后端表结构。JSON 编辑器只是提高编辑体验，不代表 `GameConfig` 运行时直接返回对象。

## 5. 现有参数分类列表

在新增参数时，请尽量复用以下已有的分类。如果确实需要新的分类，请在 `config_sub_type` 中使用清晰、达意的英文名称。

| 配置大类 (`config_type`) | 配置子类 (`config_sub_type`) | 备注 |
| :--- | :--- | :--- |
| `world` | `0` | 默认的世界/频道配置，可为其他世界ID（如`1`, `2`）创建独立配置 |
| `server` | `Core` | 服务器核心功能 |
| `server` | `Game Mechanics` | 核心游戏机制与玩法 |
| `server` | `Safe` | 安全、反作弊、账号相关 |
| `server` | `Net` | 网络与连接相关 |
| `server` | `Debug` | 调试与日志相关 |
| `server` | `GM` | GM角色专属功能 |
| `server` | `CashShop` | 商城相关功能 |
| `server` | `CheatSystem` | 内置作弊/便利系统（如宠物吸物） |
| `server` | `Anti Cheat` | 主动反作弊系统 |
